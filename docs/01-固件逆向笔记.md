# 固件逆向笔记

记录这个复刻版里**每一个数字和贴图是从固件的哪个字节来的**。
结论分三档：**已实锤**（有字节/实机双重证据）/ **有把握的推断** / **推测**。下面会标明。

---

## 1. 固件文件布局

V22 升级包里与农场相关的两个文件：

| 文件 | 作用 |
|---|---|
| `T5app.upg`（约 24 MB） | 程序本体。内含农场 UI 的**全部中文文案** |
| `T5AppRes.dat`（约 592 MB） | 资源容器，49 个 `FDVER1/2` 子文件 = 23 作物 + 26 装饰品 |

资源注册表在 `T5app.upg @0xEFCF60`，共 49 条 × 0x25C 字节，每条给出：编号 + 在 `T5AppRes.dat` 中的绝对偏移 + `C:\××.bin` 文件名。

## 2. FDVER1 作物块结构（已实锤）

块开头是 `FDVER1\0\0` + 中文作物名，参数区在 **+0x38**：

```
[0]=解锁等级  [1]=季数  [2]=重熟等待(分, 0=一次性)  [3]=种子价格
[4]=果实售价  [5]=产量/季  [6]=收获经验  [7][8][9]=固定(2,3,7)待解
[10]=0        [11..15]=生长阶段时间表(分, 0=跳过; 末值=成熟时间)
```

再往后：

- **+0x120**：帧表，连续 `[1, offset]` 对，每作物 7~8 帧
- **+0x1C0**：命名表的偏移/长度对
- **+0x1D8**：**阶段名表**（见第 4 节）

## 3. 贴图格式（已实锤）

- **Tc**：`"Tc" + w + h` + RGB565 主图（w×h×2）+ 8bit 透明遮罩（w×h）。块长 = w×h×3+6，178 帧全部精确成立
- **TS**：`"TS" + w + h` + RGB565（w×h×2）。块长 = w×h×2+6

帧序（已实锤）：`土地 → 发芽 → 幼苗(×1~2) → 成长 → (开花) → 成熟 → 枯萎(99×44) → 果实图标(70×68)`

## 4. 每作物独立的生长阶段名（已实锤）

作物块 **+0x1D8** 起，每 **9 字节**一条 GBK 字符串，槽位为 `[种子, 阶段1..N, 成熟, 枯萎]`。

**每种作物各不相同**——这是最容易漏掉的一点：

| 作物 | 固件原始阶段名 |
|---|---|
| 蘑菇 | 种子 / **原基 / 菇蕾 / 幼菇** / 成熟 / 枯萎 |
| 大白菜 | 种子 / 发芽 / **幼苗 / 成株 / 卷心** / 成熟 / 枯萎 |
| 小麦 | 种子 / 发芽 / 小叶子 / 大叶子 / **幼穗** / 成熟 / 枯萎 |
| 桃子 | 种子 / 发芽 / **开花 / 小叶子 / 大叶子** / 成熟 / 枯萎（先花后叶） |
| 白萝卜 | 种子 / 发芽 / 小叶子 / 大叶子 / 成熟 / 枯萎（无开花） |
| 其余多数 | 种子 / 发芽 / 小叶子 / 大叶子 / 开花 / 成熟 / 枯萎 |

映射规则：`阶段 i 的名字 = 名字表[ i+1 ]`（因为 `名字表[0]` 是「种子」）。

已导出到 `data/stage_names.json`。

## 5. 多季作物的重熟机制（已实锤，13/13）

固件里只有一个字段叫「重熟等待」，没写"收获后回到哪个阶段"。
但把 23 种作物摊开对比，发现一条**零例外的关系**：

```
重熟时间 = 成熟时间 − 大叶子阶段起点（第 3 个阶段边界）
```

| 作物 | 成熟 | 大叶子起点 | 差值 | 固件重熟字段 |
|---|---|---|---|---|
| 苹果 | 1260 | 720 | 540 | 540 ✓ |
| 石榴 | 3120 | 1800 | 1320 | 1320 ✓ |
| 杨梅 | 1860 | 1020 | 840 | 840 ✓ |
| 辣椒 | 1200 | 660 | 540 | 540 ✓ |

13 个带重熟参数的作物全部成立（含辣椒这个"1 季却带重熟"的特例）。

**推论**：原版多季作物收获后，进度回到**大叶子阶段起点**，再长「重熟时间」走完开花→成熟。
这也解释了为什么重熟时间恒为总时长的 40%~45%（= 最后两个阶段之和）。

复刻版 v0.5 起按此实现。

## 7. 存档格式（已实锤，来自历史工作）

`FARMSET.DAT` 3238 字节，魔数 `FARM0003`，无加密无校验：

- 等级 @0x10，经验 @0x08，金币 @0x0C
- 地块表 @0x7F0，15 块 × 60 字节，含：开垦标记、作物 ID、阶段编号、时长、已生长分钟、产量

存档中「已生长分钟」字段曾被用于二次验证番茄的阶段表（1020 分钟）✓

## 8. 明确**没有**找到的内容

- **作物背景故事 / 风味文本**：24 万行字符串全域搜索过，固件里没有。所以复刻版的作物详情面板只呈现数据，不编故事
- 参数区 +0xC8 / +0xD8 两组各 4 个 u32：数值 0~74、两组高度相似、跨作物无规律，暂判定为未知/未使用字段，**不是**"收获后回退阶段"
- 常数字段 `[7][8][9] = 2,3,7` 的含义仍未解
